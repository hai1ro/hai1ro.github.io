# 做了一个网页版马里奥，零依赖纯手写

最近用 **原生 Canvas + JavaScript** 写了一个马里奥风格的横版过关游戏。没有用任何框架、没有任何外部资源——精灵图是代码里画出来的像素画，音效是 WebAudio 现场合成的。整包就是一个 HTML 文件。

可以直接在下面玩，也可以[全屏打开](/mario/)。

> 📱 手机上打开也会自动显示触屏虚拟按键，可以直接玩。

## 玩法与操作

- `← →` / `A D`：移动
- `↑` / `空格` / `Z`：跳跃（**按住跳得更高，松开立刻截断**，这是马里奥手感的灵魂）
- `Enter`：开始游戏
- `P`：暂停 · `M`：静音

关卡是致敬 SMB 1-1 的一关：问号砖顶金币、蘑菇变身变大、砖块可撞碎（大个子才能撞碎）、栗子怪踩扁得分、水管、浮空金币、坑、楼梯、终点旗杆和城堡。300 秒倒计时、3 条命、通关按剩余时间加分。

## 实现要点

### 手感优先的物理

平台跳跃游戏好不好玩，全在物理参数。我按 60fps 固定步长调了一组参数：

| 参数 | 值 | 说明 |
|------|----|------|
| 重力 | 0.5 px/frame² | 下落加速 |
| 起跳速度 | -13（大个子 -14.5） | 最高约 4 格方块 |
| 最大跑速 | 4.2 px/frame | 加速 0.35/帧，急停有滑动 |
| 踩踏弹跳 | -7.5 | 踩敌人后的反弹 |
| 土狼时间 | 6 帧 | 走出平台边缘还能跳 |
| 跳跃缓冲 | 8 帧 | 落地前按跳不会丢 |

碰撞是经典的「先水平后垂直」逐轴解算：水平碰撞归零 vx、垂直碰撞区分「落地」和「顶头」，顶头会触发砖块判定（碎砖 / 弹砖 / 出道具）。

### 像素画是代码生成的

所有角色都是 12 列宽、字符映射颜色的像素矩阵，绘制时按像素填色：

```js
const M_STAND = [
  "....RRRR....",
  "...RRRRRR...",
  "..RRRRRRRR..",
  "..SSSSSSSS..",
  ".SKSSSSSKSS.",
  ".SHHSSSSHHS.",
  "..BBBBBBBB..",
  ".BBYBBBBYBB.",
  "WW.BB..BB.WW",
  "..TT..TT....",
];
```

R 是红帽子、S 是皮肤、B 是蓝色背带裤、T 是鞋子。小马里奥、大马里奥、走路/跳跃各帧、栗子怪、蘑菇、金币都是这么画的，想改外观直接改字符就行。

### 音效是 WebAudio 现场合成的

没有任何音频文件，全部用振荡器生成——跳跃是上滑音、金币是经典的双音、踩扁是下滑音、通关是一段小号琶音：

```js
case 'coin': tone(988, 0.07, 'square', 0.09); tone(1319, 0.28, 'square', 0.09, 0.07); break;
```

浏览器要求用户手势后才能出声，所以音频上下文在第一次按键时才创建。

## 怎么验证它没写崩

写完不能只靠"看着能跑"。我写了一个 Node 冒烟测试（`public/mario/check.cjs`）：用 Proxy 把 canvas/DOM 全部 stub 掉，在 Node 里直接驱动游戏逻辑跑了上万帧，断言：

- 加载无异常、Enter 能开始游戏
- 按住右键 40 帧内玩家确实在前进
- 跳越敌人不崩、长跑 6000 帧无 NaN（期间踩死敌人正常得分）
- `P` 暂停后倒计时冻结
- 传送到旗杆前跑跳 → 贴旗 → 滑杆 → 走进城堡 → 通关结算 → 回到标题，剩余时间奖励正确入账

这轮测试还真抓到一个 bug：渲染里引用了一个没定义的 `camY`，浏览器里打开才看得到，Node 一跑就暴露了。

```bash
node public/mario/check.cjs
# ALL PASS
```
