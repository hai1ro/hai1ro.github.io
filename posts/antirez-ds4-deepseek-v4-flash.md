# Redis 作者再出手：ds4 —— 只为 DeepSeek V4 Flash 而生的本地推理引擎

> 284B 总参数、13B 激活参数、100 万 token 上下文窗口——在一台 MacBook Pro 上以 26 tok/s 的速度跑起来。这不是科幻，这是 antirez 上周开源的项目。

如果你不熟悉 **Salvatore Sanfilippo（antirez）**：他是 Redis 的创造者，一个以"少即是多"为信仰的 C 语言工匠。十年前他用几万行精妙的 C 代码定义了全球最流行的内存数据库，如今他带着同样的工程哲学闯入了本地 AI 推理这个火热的战场。

他这次的作品叫 **[ds4](https://github.com/antirez/ds4)**（代号 DwarfStar / 矮星），发布不到一周就斩获了 **12,400+ Stars**。它不是什么通用推理框架，而是为 DeepSeek V4 Flash 量身定做的专用引擎——一条从模型加载到 Agent 工具的完整链路。

---

## 为什么要给一个模型造专属引擎？

在开源大模型遍地开花的今天，真正的瓶颈早就不是**能不能下载权重**，而是**能不能在本地跑起来**。

DeepSeek V4 Flash 是一个非常特殊的模型：

| 指标 | 数值 |
|---|---|
| 总参数量 | 284B（MoE 架构） |
| 激活参数 | 13B/ token |
| 上下文窗口 | 1,000,000 token |
| 架构复杂度 | 路由 MoE + 共享专家 + MLA 注意力压缩 |

把这样一个庞然大物塞进 128GB 内存的 MacBook，同时还要保留可用的上下文长度和可接受的生成速度——这需要一套从头设计的工程方案。通用的 GGUF runner（比如 llama.cpp）当然能加载它，但要做**极致优化**，就必须在每一层上做取舍。

antirez 的答案就是：**不追求通用，只做一件专精的事**。

---

## ds4 的四大核心设计

### 1. Metal / CUDA 优先的推理图

ds4 的主路径是 **Apple Metal**（macOS）和 **NVIDIA CUDA**（Linux）。没有 PyTorch，没有 ONNX Runtime，没有中间层——从 token 输入到 logits 输出的整条计算图都是手写优化的。

- **Metal 路径**：针对 M3 Max / M5 Max / M3 Ultra 做图级别优化，带 chunked prefill 和 KV checkpoint 复用
- **CUDA 路径**：特别适配 DGX Spark（GB10），也支持通用 CUDA GPU
- **CPU 路径**：仅用于诊断和正确性校验（macOS 上甚至会触发内核 bug……）

### 2. 非对称量化：把 284B 压到 81GB

这是 ds4 能在 128GB MacBook 上跑起来的核心秘密。它不是简单地把所有参数压成 2-bit，而是采用了**极度不对称的量化策略**：

```
路由 MoE 专家的 up/gate  →  IQ2_XXS（2-bit）
路由 MoE 专家的 down     →  Q2_K（2-bit）
共享专家、投影层、路由层  →  保持高精度（F16 / Q8）
注意力层、输出头         →  Q8 / F16
```

为什么这样可行？因为 MoE 模型的**路由专家占了绝大部分参数体积**，但它们对精度的敏感度相对较低。而共享专家和路由网络虽然参数量小，却对最终输出质量影响巨大——保留高精度是最划算的投资。

结果：**q2 量化后的完整模型仅约 81GB**，在 128GB 统一内存的 MacBook 上还剩下约 47GB 给 KV Cache 和系统开销，足以支撑 100K~300K token 的实际上下文窗口。

### 3. KV Cache 是"磁盘一等公民"

传统观念认为 KV Cache 必须放在内存里。但 antirez 提出了一个不同的思路：

> 压缩 KV Cache（DeepSeek V4 的 MLA 机制使得 KV 极其紧凑）+ 现代 MacBook 的极快 SSD = KV Cache 可以成为磁盘上的持久化产物。

这意味着：

- **长文档分析后**，KV 状态可以落盘保存
- **下次打开同一个会话**，无需重新 prefill，直接恢复状态继续对话
- **Agent 长时间任务**可以随时暂停、恢复，不用怕内存不够

ds4-server 还支持**前缀匹配复用**：如果新请求的 token 前缀与已有缓存匹配，自动跳过重复的 prefill 阶段。这对 Agent 场景尤其重要——反复发送相同的系统提示词和上下文不再消耗额外计算。

### 4. 原生 Coding Agent：从推理到工具调用一气呵成

ds4 内置了一个**不与推理引擎走 socket/API 边界**的原生 coding agent（`ds4-agent`）：

- 推理和工具调用在同一个进程中，**零序列化开销**
- KV 状态就是会话的"真值"——不存在状态不一致的可能
- 支持 `/save`、`/list`、`/switch`、`/strip` 等会话管理命令
- 工具调用直接走 DeepSeek 原生格式，无需转成 DSML 或其他中间格式

antirez 的评价很诚实："ds4-agent 目前是 alpha 质量，但架构方向是对的。"

## 实战性能：数字不会说谎

以下数据来自官方 README，在 MacBook Pro M3 Max（128GB）上使用 q2 量化模型：

| 场景 | 提示长度 | Prefill 速度 | 生成速度 |
|---|---|---|---|
| 短对话 | 短 prompt | 58.52 t/s | **26.68 t/s** |
| 长文档 | 11,709 token | 250.11 t/s | **21.47 t/s** |

换成 M5 Max（128GB），数字更猛：

| 场景 | 提示长度 | Prefill 速度 | 生成速度 |
|---|---|---|---|
| 短对话 | 短 prompt | 87.25 t/s | **34.27 t/s** |
| 长文档 | 11,707 token | 463.44 t/s | **25.90 t/s** |

对于一个 284B 参数的模型来说，**26~34 tok/s 的本地生成速度**是真正可用的。打字聊天的体验几乎无延迟，Agent 工具调用也足够快。

更令人兴奋的是**分布式推理**的潜力。用两台 M5 Max（128GB）通过 Thunderbolt 5 连接，可以跑 q4 量化的完整模型：

| Prompt 长度 | 单机 q2 参考 | 双机 q4 分布式 | 加速比 |
|---|---|---|---|
| 9,421 token | 421.70 t/s | 582.22 t/s | 1.38x |
| 28,684 token | 405.30 t/s | 674.16 t/s | 1.66x |
| 63,819 token | 353.62 t/s | 654.79 t/s | **1.85x** |

prefill 阶段通过流水线并行实现近线性加速，长上下文场景下收益尤其明显。

## "专精胜过泛用"——antirez 的工程哲学

读 ds4 的代码和文档，你能感受到一种强烈的 antirez 风格：**克制、务实、坦诚**。

README 里毫不避讳地说：

> "这个软件是在 GPT 5.5 的强力辅助下开发的，人类负责想法、测试和调试。如果你不喜欢 AI 写的代码，这个项目不适合你。"

他对 llama.cpp 和 GGML 的致谢也写得很真诚：ds4 不链接 GGML，但它的量化格式、kernel 设计、GGUF 生态都深受其启发。这是开源精神的正确打开方式——站在巨人的肩膀上，但不试图成为另一个巨人。

"专精而非泛用"的选择也体现在项目结构上：

- 不支持任意 GGUF，只跑官方发布的特定量化文件
- 不做通用 API gateway，Server 只开一个 Metal worker
- 不追榜单，eval 工具只用于回归测试而非刷分

antirez 的目标很明确：**把一件事情做深、做透、做到可用，而不是做广、做浅、做给别人看**。

## 它意味着什么：本地 AI 的"Redis 时刻"

2010 年前后，Redis 的出现改变了人们对数据库的认知：原来缓存可以这么快、这么简洁、这么"刚刚好"。它不做 SQL、不做事务、不做复杂查询——但它把内存数据结构这件事做到了极致，最终成为全球最流行的数据库之一。

ds4 有类似的潜力。在所有人都在追逐"下一个更强模型"的时候，antirez 停下来问了一个更实际的问题：**现有最强的模型，能不能在个人设备上真正跑起来？**

他的答案是：**可以，只要你愿意为它写一个专用引擎。**

这对于 AI 落地的意义是深远的：

1. **从云端到本地**：当 284B 的 MoE 模型可以在 MacBook 上流畅运行时，很多对延迟敏感、对隐私有要求的场景就不再需要依赖云端 API
2. **Agent 的真正基础设施**：本地推理 + KV 持久化 + 原生工具调用 = Agent 可以"活"在你的机器上，而不是在别人的服务器里
3. **开放模型的竞争力**：如果 DeepSeek V4 Flash 可以在个人设备上稳定运行，那么开放模型和闭源 API 之间的鸿沟又缩小了一大块

## 现在能跑吗？能，但要有心理准备

**硬件门槛**：

- 最低：MacBook Pro M3 Max（128GB）或更高
- 推荐：Mac Studio M3 Ultra（512GB）——可以跑 PRO 版本
- Linux：DGX Spark 或其他 CUDA 设备

**快速上手**：

```bash
git clone https://github.com/antirez/ds4.git
cd ds4
./download_model.sh q2-imatrix   # 128GB 机器
make                              # macOS Metal
./ds4                             # 交互式对话
```

**当前状态**：Beta 质量。antirez 自己说"推理和模型服务是复杂的事情，这个项目才存在了几天，需要几个月才能达到更稳定的状态"。但项目承诺保持可用状态，并持续改进。

如果你正好有一台高配 MacBook，又对本地 AI 充满好奇——不妨现在就去试试。这可能是你在 2025 年遇见的最有趣的 C 语言项目。
